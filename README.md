# Copilot · AI 面试副驾

> 手机练习端（iPhone PWA，无需服务器）：见 [MOBILE.md](./MOBILE.md)。入口 `/m`，数据从「标准问答」页的「同步到手机」过去。

围绕**你自己的真实简历与项目**，把「准备 → 演练 → 实战辅助 → 复盘」串成一条闭环的面试工作台。

不是搜题工具，也不是模拟题库。主路径是**标准问答**：把面试官可能问的题、同义问法和完整答案提前写进去，实战命中后原样显示，不经过模型改写，也没有思考延迟；没命中再由模型结合简历、JD、**自定义答题指令**和答题框架现场生成。技能卡退到可选上下文，只作为个人事实的补充。

v1.7 重点修了三件事：题库「工作岗位调剂 / 工作地点调剂」互相串答案；未命中题模型先思考 3~10 秒；系统音频转写从「分片上传」升级为**腾讯云实时流式**。v1.7.1 新增 `/layout` 窗口布局演示（置顶 / 透明度 / 多显示器），并明确标注**共享中可见**。v1.8.4 新增**多公司面试档案**（一家公司一份，题库/文档/调研互相隔离；面试前先选本次要面的公司）、**公司 / 岗位联网调研**、**面试专注模式**（全屏、宽答稿、只留问题与答案）；同时收紧标准问答匹配、压缩实时提示词降低首字延迟，并修复腾讯云实时 ASR 长静音 4008 断线、自动重连切回流式。

## 快速开始

```bash
npm install
npm run dev          # http://localhost:3300
npm run check:qa     # 题库匹配回归用例（调剂 / 薪资 / 优缺点 / 公司动机）
npm run check:asr    # 8761 实时转写桥连通性
```

首次打开是空态，可以直接点「载入示例档案」，会写入一份后端简历 + JD + 6 道标准问答 + 4 张技能卡 + 1 场已复盘的模拟面试，用来快速看清整条链路。

生产构建：

```bash
npm run build
npm start            # http://localhost:3300
```

> 需要 Node 18+。项目默认端口 3300，改 `package.json` 里的 `-p` 即可。

### 桌面端（Windows，不想开网页就用这个）

已经打好包：

| 文件 | 用法 |
| --- | --- |
| `dist/win-unpacked/面试副驾.exe` | 免安装版（1.8.4）。双击直接用，可以自己「发送到 → 桌面快捷方式」 |
| `dist/面试副驾-Setup-1.8.4.exe` | 1.8.4 安装包（per-user，一键安装，不需要管理员权限） |

> 本机更新：改 `package.json` 的 `version`（必须比已安装版本大）→ `npm run release:local` → 打开已安装的 1.8.4 → 设置 → 关于与更新 → 检查更新。首次需要先手动装一次 1.8.4 完整包；之后不用再去 `dist` 里找安装包。

装上之后就跟普通软件一样：双击图标开窗，没有地址栏，没有浏览器标签，关掉窗口即退出。

**1.1.0 起支持直接听会议里的对方**：桌面端用 Windows 的 loopback 抓系统音频轨，不经过麦克风，戴耳机也能听到，也不会把你的声音混进去。1.7.0 默认走本机 `8761` 的腾讯云实时桥（密钥在桥的配置里）；桥没启动时，才需要配一个 ASR Key 走分片兜底，见下面的「配置模型」。

怎么做到的：Electron 主进程里直接 `require` Next 的 standalone 服务（`127.0.0.1:38217`），再开窗口加载它。所以 `/api/chat` 的 SSE 代理、`getDisplayMedia` 截图、IndexedDB 存档全都照常工作，和网页版是同一套代码、同一份数据。

**端口固定 38217 是有原因的**：IndexedDB / localStorage 按 origin 隔离，端口一变你之前存的档案就"消失"了。被占用时才会顺延到 38218，那种情况下数据是另一份。

自己重新打包：

```bash
npm run desktop:build     # 只生成 standalone 产物（改完代码要先跑这个）
npm run desktop           # 开发用，直接开窗
npm run desktop:portable  # 打免安装目录
npm run desktop:dist      # 打安装包
```

### 配置模型

右上角 ⚙ 设置，或 `Ctrl/⌘ + K` → 打开设置：

| 字段 | 说明 |
| --- | --- |
| API Base URL | OpenAI 兼容地址，内置 OpenAI / DeepSeek / 通义 / 智谱 / 月之暗面 / 本地 Ollama 预设 |
| API Key | 只存在本机 `localStorage`，请求经 `/api/chat` 由服务端转发 |
| Model | 例如 `gpt-4o-mini`、`deepseek-chat`、`qwen-plus` |
| 温度 | 0 ~ 1，默认 0.4 |

**出站请求限制**：`/api/chat` 和 `/api/asr` 只转发到 `http` / `https` 地址，不跟随重定向，并拒绝云元数据地址和 link-local 网段；本机地址只放行 `127.0.0.1` 上的 `7863`（本机 wb2api / 模型网关）、`8760`（本地 router / 模型网关）、`8765`（本地 ASR）和 `11434`（Ollama）。私网 `10 / 172.16 / 192.168` 保持可用，方便接自建网关。这样即使有人把 Base URL 填成本机任意端口，也不能借服务端去探测无关服务。注意：这里只做字面地址判断，不做 DNS 解析，域名解析到内网地址的情况不在拦截范围内。

设置里还有一块**语音识别（ASR）**，桌面端的「对方声音」靠它工作。v1.7 的默认链路是**真流式**：

```
系统音频（Windows loopback）
  → 16k / 16bit / 单声道 PCM（100ms 一包，比 200ms 更早送进云端）
  → ws://127.0.0.1:8761（stream_bridge.py）
  → 腾讯云实时语音识别 16k_zh
  → partial 边说边出字；静音窗口默认 700ms，出 final
  → 80ms 内触发答稿
```

静音窗口是速度和质量的分界：实测同一段 10 秒中文，600ms 能完整断句，500ms 会在句中停顿处提前切段（把一句话拆成两个 final，答稿会从半句开始）。600~700ms 是这台机器上的稳定区间，设置里的数值会直接传给桥的 `silence_ms`。

v1.8.1 修复了腾讯云实时 ASR 的 4008 断线：桥在静音期每 3 秒补一帧 100ms 静音 PCM 保活；前端在实时流断开时先用分片兜底，每 6 秒重试 8761，重连成功后自动切回流式，界面显示「重连中 / 已恢复」，不会永久停在分片链路。

为什么选腾讯云实时 `16k_zh`：它返回带标点的中间结果，首字实测 0.6~1.5s；本地 faster-whisper large-v3 更私密、术语更稳，但 final 要 1.4~4s，适合做兜底而不是主链路。设置里可以三选一：

| 模式 | 走哪条 | 适用 |
| --- | --- | --- |
| 自动（默认） | 先连 8761；连不上自动回退分片 | 绝大多数场景 |
| 强制流式 | 只用 8761 | 确认桥稳定、想压低延迟 |
| 只用分片 | 8765 / 云端 `/audio/transcriptions` | 8761 没启动，或想完全本地 |

桥没启动时，在 `asr` 目录运行 `start_stream.bat`（或重开机时由 `autostart_asr.vbs` 拉起）。桥的 `stream_config.json` 里 `mode=tencent` 表示腾讯云，`mode=local` 表示本地 large-v3；密钥只在桥这一侧，渲染进程拿不到。

分片兜底仍然保留：`ASR Base URL` 填到 `/v1`，`ASR Model` 默认 `whisper-1`，也兼容 `FunAudioLLM/SenseVoiceSmall` 等。只需要支持 `POST /audio/transcriptions`（multipart 上传 wav、返回 `{text}`）的服务。

#### 低延迟模型

实测（同一台机器、同一个问题、取首个正文 token）：

| 模型 | 首字 | 说明 |
| --- | --- | --- |
| `cn:glm-5.3-flash` | ~1.6s | 非推理模型，稳定，默认极速兜底 |
| `cn:deepseek-v4.1-flash`（默认） | 3~10s 甚至更久 | 先输出 `reasoning_content`，正文被拖慢 |
| `cn:deepseek-v4.1-flash` + `reasoning_effort=none` | ~1.2s | v1.7 自动加这个参数，正文直接出 |

所以 v1.7 在设置里加了「关闭推理链（DeepSeek 等）」开关，默认开启；`/api/chat` 只对 `deepseek-v4.1 / reasoner` 这类模型带 `reasoning_effort=none`，普通模型不受影响。网关不认这个参数时，服务端会自动去掉并重试一次。

未命中标准问答时，App 默认走「极速兜底」：按 Base 自动选非推理模型（本机 8760 → `cn:glm-5.3-flash`，本机 7863 → `deepseek-v4.1-flash`，通义 → `qwen-flash`，智谱 → `glm-4-flash`，DeepSeek → `deepseek-chat`），并追加「180~220 字、先结论后依据」的实时约束；同时把材料从「最多 4 卡 + 4 段」压到「最多 2 卡 + 2 段」，输出封顶 220/360/520 token。标准问答命中时不经过模型，不受模型延迟影响。

**不填 Key 也能用**：自动进入「演示模式」，答稿、追问、洞察、点评都改用本地规则合成，并在界面上明确标注（`演示模式` / `演示合成` / `本地启发式` / `未使用你的个人材料`）。演示模式不会伪造不存在的接口调用。

### 多公司档案与面试前选择（v1.8.4）

一家公司一份档案，互不覆盖：

- 面试档案页右上角、左侧栏底部都有「新建面试档案」；
- 每份档案独立保存公司、岗位、轮次、简历、JD、题库、技能卡、调研结果和历史场次；
- `/live` 开始前必须先在「本次面试档案」里选择这次要面的公司；切换档案会重新加载该档案的题库/文档，加载完成前不能点「开始本轮」；
- 开始本轮后，快照里只包含选中档案的题库、文档和公司调研，不会再去读其他公司的题库；顶部也会显示当前公司名。

### 公司 / 岗位调研（v1.8）

面试档案页向下有一块「公司 / 岗位调研」。填好公司、岗位并上传 JD 后点「开始调研」：

1. 服务端按「公司 + 岗位 + 面试」生成多组检索词，抓公开搜索结果（牛客、小红书、抖音、知乎、CSDN、BOSS 直聘、公司官网等公开页面摘要）；
2. 模型分两路归纳：一路写公司背景、业务/文化、面试流程/风格、岗位能力和风险点；一路专门整理 8~12 道高频问题及回答方向；
3. 结果存在本机 IndexedDB 的 `research:<profileId>`，不上传第三方；
4. 点「开始本轮」时，调研结果和题库、文档一起冻结进快照，面试中模型会围绕目标公司的业务、岗位要求和面试风格作答；中途重新调研不影响已经开始的这一轮。

边界：只读取公开搜索摘要，不登录小红书/抖音，不绕过验证码；来源少或资料冲突时会明确写「资料不足」，不编造公司营收、面试官姓名和具体薪资。调研结果里的「推断」会标明，回答时也不会把推断说成事实。

v1.8.4 修复了「没有抓到公开搜索结果」：360 桌面搜索在无 Cookie 时常返回「访问异常页面」，现在默认走 `m.so.com` 移动结果页，失败自动回退桌面 360 和 Bing；检索词也会自动缩短公司名、拆出岗位核心词，并把 JD 里的 5G/网络运维/传输等关键词带进查询。你不需要自己提供网页链接。

## 关键机制

### 标准问答是主路径

`lib/qaMatch.ts` 只拿**题目 + 同义问法**做匹配，不拿答案。v1.8 在 v1.7 的 IDF 加权覆盖上又加了三道「宁可不答，也不答错」的门：

- 先做等价同义替换（工资→薪资、优势→优点、工作地点→地点），换说法能对上
- 中文同时看单字和二元词；用**整个题库的动态 IDF** 给词加权：两道题都有的「工作 / 调剂」权重低，只在一道题里出现的「岗位 / 地点」权重高
- **双向覆盖**：既看问法被问题覆盖多少，也看问题被问法覆盖多少；只覆盖一半的弱相关问题直接拒绝
- **二元词 Dice**：只共享「公司 / 工作」这类高频词、语序和搭配对不上的，不命中
- **意图 / 对象冲突**：了解公司 ≠ 为什么选择公司，优点 ≠ 缺点，岗位调剂 ≠ 地点调剂，当前薪资 ≠ 期望薪资，加班 ≠ 出差；问题里同时问两个对象、题库只覆盖一个时，也拒绝
- **歧义拒绝**：第一名和第二名（不同题）分差 < 0.08 时直接不命中，宁可让模型现场答，也不把另一道题的标准答案贴出来
- 反义保护：接受 ≠ 不接受，成功案例 ≠ 失败案例
- `/qa` 页新增「命中测试」：输入一句话，直接看到会命中哪题、相似度多少、前几名差多少；同义问法重复会标红
- 命中后 `useLiveSession` 直接把准备好的答案落成 turn，不调用模型，`latencyMs` 只有匹配耗时；答案为空时自动回退模型
- 没命中才走 `lib/answer.ts` 选材 + `chatStream`，用简历、JD、技能卡、自定义指令和答题框架现场生成
- 快照会冻结 `qaIds`；本轮新增/修改问答下一轮生效

### 批量导入（70~80 题不用手敲）

1. 在 `/qa` 点「模板」，下载 `faq-template.md`
2. 把模板 + 简历 + 岗位 JD 发给 GPT / Claude，让它按格式生成 `.md`
3. 回到 `/qa` 点「导入」，选择文件或直接粘贴，预览识别到的题数
4. 点「导入」一次性写入；同题会合并同义问法并更新答案，不会重复

解析器（`lib/faqTemplate.ts`）支持两种格式：

- 模板格式：`---` 分隔，每题 `问：` / `同义：` / `答：`
- GPT 常见格式：`### 1. 题目` + `同义：` + `答：`

围栏代码块里的示例会自动忽略；答案里不要出现单独一行的 `---`。

### 技能卡是个人事实的来源，不是答题模板

一张卡包含：项目 / 时间 / 我的角色 / 背景 / **我的具体动作** / **关键决策与取舍** / **可量化结果** / 可能的追问 / 状态。

- 只有 `已确认` 的卡片会进入实战快照
- 答稿先判断题型（`lib/playbook.ts`），再决定要不要拉卡片：自我介绍 / 项目 / 经历匹配 / 行为题才用卡片，知识题 / 公司题 / 场景题不塞卡片
- 卡片里的字段是事实清单，不是话术。模型会把它讲成一段口语，而不是逐条复述
- `准备对话` 用附录 A1 的追问官提示词，一次问 1 个问题，专挑「归因不清 / 数字无源 / 取舍缺失 / 边界模糊」
- 对话结束后按 `lib/prompts.ts` 的 `EXTRACT_SYSTEM` 抽成结构化字段；未配置 Key 时用本地归类规则，**只归类不改写，不编造数字**

### 快照锁定

点「开始本轮」时，把「当前标准问答全文 + 已确认卡片全文 + 全部文档与检索片段 + 档案字段 + 自定义指令」冻结成 `snapshot`。本轮命中标准问答就直接出答案；没命中时，个人事实只引用该快照里的卡片和简历，因此前后答案不会自相矛盾。中途新增/修改问答、改档案或改指令，都下一轮生效——包括改了答案文字这种「看起来只动了一个字段」的修改，本轮读到的仍是冻结前的版本。1.7.1 之前的旧快照只存了 ID，恢复时会按 ID 回退到当前内容。

### 窗口布局演示（`/layout`）

桌面端会开一个独立的演示浮窗（`/layout-stage`），可以在主窗口里调整：

- 置顶 / 不置顶
- 40%~100% 透明度
- 主屏 / 副屏及五个停靠位置

它只改变窗口层级、透明度和位置。共享屏幕或录屏时，演示窗会完整出现在画面里；界面和 README 都明确标注「共享中可见」。

### 检索与选材

`lib/retrieval.ts`：中文按**二元切分**、英文按词切分，BM25（k1=1.3, b=0.75），同一文档最多命中 2 段。切块 420 字、重叠 60 字。技能卡另有一套基于 token 重叠的选卡打分。

`lib/qaMatch.ts`：标准问答匹配 v2。归一化去标点 → 同义替换 → 单字 + 二元词 → 题库 IDF 加权覆盖率 → 歧义拒绝 + 反义保护。短问题门槛 0.70，长问题 0.66；「工作岗位调剂」和「工作地点调剂」这类只差一个限定词的题不再互相命中。

### 自定义答题指令（AskCc 式）

`/profile` 新增「自定义答题指令」：写 3~5 条「怎么说」，例如「先给结论」「每题 30 秒」「代码默认 Python」。它只影响语气、结构、顺序和长度，不改变事实来源；模型仍然只能从简历、JD、知识库和技能卡里取事实。

点「开始本轮」时，档案字段和指令会一起冻结进 `snapshot.profile`。面试中途改档案、改指令，都不会影响已经开始的这一场；下一场才生效。这和 AskCc 的「开始面试时锁定当时的指令」是同一套做法。

`lib/answer.ts` 按题型决定材料：自我介绍带全部卡片 + 简历；项目题带相关卡片 + 简历片段；公司 / 知识 / 场景题不塞卡片，公司题只带 JD 和笔记，避免答成「我的项目经历」。右栏可以强制切换「自动 / 我的材料 / 通用」。

### 答题方法论

`lib/playbook.ts` 内置 13 类题型的识别规则和答题骨架：自我介绍、经历匹配、项目深挖、岗位理解、公司了解、知识题、场景设计、行为题、压力题、动机规划、薪资 Offer、反问环节、综合。实时场景先本地判题型（0 延迟），只把对应那一类注入提示词，避免「一张卡片答所有题」。

### 流式

前端 `lib/llm.ts` 手动解析 SSE 的 `data:` 行；服务端 `app/api/chat/route.ts` 只做透传，不落盘、不记录 Key。答稿渲染节流到一次 setState 一批，避免每个 token 重排。

## 实战怎么摆（重要）

### 对方的声音怎么进来

桌面端有两条**互相独立**的收音轨：

| 轨 | 来源 | 用途 |
| --- | --- | --- |
| 对方声音 | 系统音频（Windows loopback），**不含麦克风** | 转成文字后自动提问、自动出答稿 |
| 我的声音 | 麦克风 | 练习模式里记录你的作答 |

「对方声音」走的是 `getDisplayMedia` + Electron 的 `audio: 'loopback'`，拿到的是扬声器里正在播放的数字音频，不经过房间、不经过麦克风。所以：

- **戴耳机也能听到对方**（loopback 抓的是播放流，不是环境声）
- 不会有回声，也不会把你自己的声音混进去
- 转写走 `/api/asr` 分片上传，边说边出中间结果，停顿 0.7s 后定稿

浏览器版做不到这点（`getDisplayMedia` 在 Chrome 里要手动勾"共享音频"，且没有 loopback），所以这个能力只在桌面端。

### 麦克风的兜底

麦克风是"全收"设备，外放时会把面试官和你的声音混在一起。真要用麦克风，有三道保险：

| 保险 | 行为 |
| --- | --- |
| **推按说话** | 设置里把「拾音方式」切到「按住空格」，只采纳按住期间（含松开后 1.2s）的识别结果 |
| **答稿冷却** | 答稿生成中、以及结束后 3 秒内，新识别只记录、不自动作答 |
| **念稿检测** | 识别结果与上一份答稿字符重合度 ≥ 0.68 时判定为自激，直接丢弃并提示 |

推荐组合，按稳妥程度排序：

1. **桌面端 + 对方声音（系统音频）**（干净，不需要你开口）
2. **戴耳机 + 关掉自动作答 + 手动输入**（纯 Web 的唯一无风险姿势）
3. **外放 + 推按说话**

## 已知限制（不假装实现）

1. **纯 Web 抓不到会议里的对方声音，桌面端可以。** 桌面端走 Electron 的 `audio: 'loopback'`，能直接拿到系统播放流（已在 Windows 实测：音轨标签 `System audio`，RMS 正常）。浏览器版里 `getDisplayMedia` 拿不到 loopback，`Web Speech` 又只认默认麦克风、不能喂第二条流，所以浏览器只能用麦克风。
2. **默认 8761 是真流式，8765 / 云端分片不是。** 8761 走腾讯云 WebSocket，partial 边说边出字、final 0.55~0.9 秒；8765 的 large-v3 定稿仍要 1.4~4 秒（看题长），云端 `/audio/transcriptions` 通常 1.5~3 秒。8761 没启动或断线时，App 会自动回退分片，不会没字。
3. **Web Speech 的识别质量取决于浏览器，而且不是本地识别。** Chrome 会把音频送到 Google 的服务器转写（断网会报 `network` 错误就是这个原因）。桌面端的「对方声音」不走它，走你配置的 ASR。
4. **推按说话依赖识别启动延迟。** Web Speech 从按住到真正开始收音有 200~500ms 的空档，开口太急可能吃掉首字。
5. **首次出字取决于上游模型，但推理链可以关。** `deepseek-v4.1-flash` 默认先输出 `reasoning_content`，实测首字 3~11 秒；v1.8 自动带 `reasoning_effort=none` 后首字约 1.2 秒。极速模式还把 system prompt 从约 1.5k 字压到约 0.5k 字，历史只带 1 轮、材料压到 2 卡 + 2 段，端到端快模型基线约 2~3 秒，提前断句 + 短提示词后目标约 1.5~2.2 秒。仍建议把 `cn:glm-5.3-flash` 作为极速兜底，并在设置里用「测试连接」看首字耗时。
6. **知识类回答依赖模型本身。** 公司、行业、八股题不再强制引用卡片，模型会用自己的知识作答；具体数字可能有偏差，回答里会尽量用「我印象里」这类措辞，最终事实仍需你确认。
7. **所有答案的事实性由用户负责。** 模型只做组织和表达，不保证数字准确。
8. **截图解题依赖 `getDisplayMedia`。** 部分浏览器会把共享窗口的标签页一起截进来；模型看不清时会明确写「截图此处不清」。演示模式下读不了图片，会直接说明。
9. **PDF 扫描件提不出字。** 走 pdf.js 文本层，纯图片 PDF 会提示改用粘贴。
10. **布局演示不是反检测功能。** 它只改置顶、透明度和显示器位置，不做窗口捕获排除；共享屏幕时对面能完整看到演示窗。
